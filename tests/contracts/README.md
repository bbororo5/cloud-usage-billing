# Contract Guardrails

## 목적과 실행

승인된 경계 계약을 검사하는 Java 21 테스트 전용 모듈이다. 제품 모듈에 의존하지 않고 DB·Kafka·HTTP 서버 없이 실행한다.

```sh
./gradlew :tests:contracts:test --no-daemon
```

## 검사 범위

| 대상 | 입력 분류 | 판정 기준 |
|---|---|---|
| 이벤트 형식 | 정상, 누락, 타입·단위 오류, 금지 필드, meter 중복·누락, UInt64 상한, 밀리초 정밀도 | JSON Schema, UUID·날짜 format 검증 활성화 |
| 이벤트 의미 | 정확히 60초, 짧거나 긴 구간, 자원·시각 불일치, UTC, Compute 수량 | `docs/event-contract.md`에서 도출한 테스트 전용 오라클 |
| API 형식 | 정상·빈 응답, 오류 필드, 요청 누락, enum·limit·groupBy 경계 | OpenAPI 내 스키마와 `contracts/examples/user-api-cases.json` |
| API 선언 | 참조 연결, 사용자 세션 선언, 회사 선택 query 금지, 공통 오류, 비용 503 | 승인된 API·저장소 계약의 명시적 기대값 |

정상 예제를 먼저 검사한 뒤 한 규칙을 위반하는 예제로 검출 능력을 확인한다. 실제 스키마는 계약에서 읽되, 통과·실패 기대값은 테스트에 별도로 명시한다. API 검사는 선택한 구조·스키마 규칙이며 전체 OpenAPI 표준 적합성 lint는 아니다.

## 검증하지 않는 것

- 실제 발생기 출력·재시도 식별자/내용 유지·미완성 구간 미발행: `apps/usage-generator` 테스트와 `scripts/verify-ingestion.sh`에서 별도로 검사한다.
- 실제 BFF 응답·회사/RBAC/CSRF 강제·커서 보안·내부 정보 비노출: BFF 구현 전 실패 테스트를 추가한다. 현재 검사는 선언·예제만 확인한다.
- 기간 31일, UTC 분 경계, 단위 혼합 정렬 등의 교차 필드 동작: 입력 처리 LLD에서 검사한다. 월·가격 경계를 걸치는 사용량의 미결 정책은 임의로 고정하지 않는다.
- 금액 예제의 스키마 통과는 계산 정확성 검증이 아니다. 계산·귀속·장애 복구·DB 권한·성능은 별도 테스트 대상이다.

1~60초를 허용하던 기존 파서는 `legacy/`로 이동하고 빌드에서 제외했다. 이 모듈의 오라클 통과를 직접 소비 경로의 검증으로 간주하지 않으며 통합 검사를 별도로 실행한다. deprecated HTTP 수집의 오류 스키마도 사용자 API와 분리해 유지한다.

## 변경과 증거

기대값·검사 제외·실행 설정의 변경은 계약 변경으로 별도 검토한다. 통과를 위해 기준을 약화하지 않는다.

초기 두 API 검사에서 오류 `message` 필드 및 비용 `503` 누락으로 **2건 실패 → 계약 수정 → 2건 통과**를 확인했다. 이후 예제·경계 검사를 추가했다. 테스트 실행 결과는 `build/reports/tests/test/index.html`에 생성된다.

수량·시간 경계 33건을 추가했다. UInt64 최대값 바로 위와 모든 시각 필드의 초과 정밀도에서 **17건 실패 → 스키마 제한 추가 → 통과**를 확인했다. 최대값 인접 수량은 `BigInteger`로 만들어 반올림 없이 검사한다. 총 이벤트 78건·API 32건이며 실제 ClickHouse 변환·저장 검증과는 구분한다.

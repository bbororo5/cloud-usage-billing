# ADR-008: 과금 비인지 사용량 수집과 후행 귀속

## 상태

승인 — 테넌트 격리의 구체적 조회 방식은 후속 결정

## 배경

VM은 자신의 1분 사용량과 출처만 알리며 회사·가격·Kafka·조회 시스템을 알지 않는다. VM은 클라우드 사업자 소유이고 회사는 일정 기간 점유하므로, 현재 회사 관계만으로 과거 사용량을 귀속하면 안 된다.

## 요구사항

- 외부 이벤트는 CloudEvents 형식의 원시 측정값만 담는다.
- 같은 VM의 이벤트 순서를 유지하고 재전송을 판별한다.
- 사용 시점의 회사–VM 점유 관계로 비용을 귀속한다.
- 점유 관계를 찾지 못한 사용량은 월간 확정에서 누락하지 않는다.

## 선택지

- 수신 시 회사·SKU를 보강해 Kafka와 ClickHouse에 저장
- 회사와 무관하게 원시 사용량을 저장하고 조회·정산 시 귀속

## 트레이드오프 분석

| 기준 | 수신 시 보강 | 후행 귀속 |
|---|---|---|
| VM 계약 | 과금 문맥이 입력 경계로 번질 수 있다. | VM은 출처와 측정값만 안다. |
| 수집 의존성 | 회사 매핑 장애가 수집을 막을 수 있다. | 매핑과 무관하게 원시 사용량을 보존한다. |
| 과거 귀속 | 기록 시점의 회사를 행에 고정한다. | 점유 이력과 사용 구간을 정확히 결합해야 한다. |
| 조회·격리 | 회사 조건으로 직접 조회하기 쉽다. | PostgreSQL 범위를 ClickHouse 조회에 안전하게 적용해야 한다. |

## 결정

원시 사용량을 먼저 저장하고 회사 귀속은 나중에 수행한다.

- CloudEvents `source`는 VM 출처를 식별하며 Kafka key로 사용한다.
- 외부 이벤트와 ClickHouse 원시 원장에는 `BillingAccountId`를 넣지 않는다.
- PostgreSQL이 회사–VM 점유 구간 `[validFrom, validTo)`의 정답을 소유한다.
- FOCUS 용어는 원시 이벤트가 아니라 귀속·가격 결합 이후의 비용 모델에 적용한다.
- 점유 관계가 없는 source는 미귀속 사용량으로 탐지하고 월간 확정을 차단한다.

## 결과

수집 파이프라인은 과금 도메인과 분리된다. 대신 조회·정산은 사용 구간과 점유 구간을 결합해야 하며, 이 결합을 이용한 테넌트 격리 방식은 ADR-006의 후속 논의에서 확정한다.

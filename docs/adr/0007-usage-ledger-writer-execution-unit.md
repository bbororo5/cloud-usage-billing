# ADR-007: 사용량 원장 적재 실행 단위

## 상태

승인

## 배경

ADR-003에서 별도 스트림 집계 엔진은 제거했지만 Kafka 이벤트를 서비스별 레코드로 변환해 ClickHouse에 적재하는 책임은 남는다. 이 책임의 장애가 이벤트 접수를 중단시켜서는 안 된다.

## 요구사항

- ClickHouse 장애·적체 중에도 Kafka 접수는 계속한다.
- 적재 성공 뒤에만 consumer offset을 진행한다.
- 복구 시 같은 이벤트가 다시 적재돼도 조회 결과는 같다.

## 선택지와 트레이드오프

| 선택지 | 장점 | 부담 |
|---|---|---|
| 이벤트 접수 프로세스에 포함 | 실행 단위가 적다. | 소비자 장애와 자원 고갈이 HTTP 접수에 전파될 수 있다. |
| 원장 적재기 분리 | 접수와 독립 재시작·확장·적체 복구가 가능하다. | 배포·관찰 대상이 하나 늘어난다. |

## 결정

Kafka → ClickHouse 처리를 `usage-ledger-writer` 독립 실행 단위로 둔다.

- 이벤트 접수는 Kafka 내구성 기록까지만 책임진다.
- 원장 적재기는 이벤트를 3개 사용량 행으로 변환해 batch insert한다.
- ClickHouse 성공 뒤 offset을 commit한다.
- 비용을 계산하거나 선집계 결과를 소유하지 않는다.

## 결과

ClickHouse 장애가 이벤트 접수 프로세스에 직접 전파되지 않는다. 대신 별도 consumer lag·실패·재시작을 운영하고 테스트해야 한다.

# ADR-011: 점유·귀속 워커 분리

## 상태

승인 — 2026-09-25. 실행 구조 결정이며 구현·장애 검증 전이다.

## 배경

원시 사용량은 Kafka에서 ClickHouse로 직접 적재한다. 별도로 점유 사실을 반영하고, 저장된 사용량을 과거 회사에 귀속하는 상시 처리가 필요하다.

## 요구사항

- BFF는 원시 사용량에 접근하지 않는다.
- 귀속 재처리와 월간 정산의 장애·재시작이 사용자 API에 직접 결합되지 않는다.
- 사용량 수집은 귀속 처리 중단과 독립적으로 계속한다.

## 선택지

BFF 포함 / 월간 배치 포함 / 점유·귀속 워커 하나로 분리.

## 트레이드오프 분석

| 선택 | 이점 | 부담·판단 |
|---|---|---|
| BFF 포함 | 실행 단위가 적음 | 원시 데이터 권한·상시 재처리 부하가 API 프로세스에 들어가 기존 접근 경계와 충돌한다. |
| 월간 배치 포함 | 실행 단위가 적음 | 상시 처리와 월간 대량 작업의 실행·복구 수명이 결합된다. |
| 워커 분리 | API·정산과 권한·재시작·처리량 분리 | 배포·관측 대상 하나가 늘어난다. 격리를 위해 선택한다. |

## 결정

점유 이력과 사용량 귀속을 워커 하나의 두 모듈로 둔다. 점유 모듈은 별도 Kafka 점유 토픽을 소비해 PostgreSQL 이력·확인 범위·캐시를 갱신한다. 귀속 모듈은 ClickHouse 원시 사용량을 읽어 회사별 귀속 데이터와 처리·공개 상태를 기록한다.

사용량 토픽의 직접 적재 경로는 유지한다. 워커는 원장 적재기나 선집계 엔진이 아니다. BFF·배치는 워커를 동기 호출하지 않고 저장소의 결과·공개 상태를 읽는다. 캐시 제품·배포 방식은 미정이다.

## 결과

워커 중단은 새 귀속을 지연시키며 안전하게 공개된 기존 결과는 조회할 수 있다. 두 내부 모듈의 프로세스 장애와 공유 DB의 자원 경합까지 격리되지는 않는다.

[HLD](../occupancy-attribution-hld.md)의 최소 권한·부분 실패·재시작·정정 중 공개 차단을 LLD와 연결 테스트로 검증한다. 회사 불명 오류의 전체 회사 정산 보류는 이번 승인에 포함하지 않는다.

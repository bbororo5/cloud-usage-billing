# ADR Roadmap

중요한 기술 선택만 ADR로 남기며, 필요한 시점에 하나씩 결정한다.

| ADR | 의제 | 시점 | 상태 |
|---|---|---|---|
| [001](0001-execution-unit-structure.md) | 실행 단위 구성 | 논리 아키텍처 확정 후 | 승인 |
| 002 | 이벤트 전달과 처리 보장 | 이벤트 접수 구현 전 | 예정 |
| 003 | 데이터 저장소 역할과 제품 | 데이터 모델 작성 전 | 예정 |
| 004 | 현재 월 집계 방식 | 집계 구현 전 | 예정 |
| 005 | 월간 정산 실행 방식 | 정산 구현 전 | 예정 |
| 006 | 인증 상태 관리 | 로그인 구현 전 | 예정 |
| 007 | 테넌트·RBAC 강제 방식 | 사용자 API 구현 전 | 예정 |

캐시와 배포 환경은 성능 측정이나 실제 배포에서 중요한 선택이 생길 때만 ADR로 추가한다.

ADR은 `상태 → 배경 → 대안 → 결정 → 결과`를 기본으로 하며, 대안이 사실상 없는 경우 불필요한 목차는 생략한다.

# 프로젝트 요구사항

## 1. 목표

클라우드 사용량 이벤트를 수집·집계해 최근 월 누적 예상 금액과 월간 확정 금액을 제공한다.

- 데이터 파이프라인, 배치 처리, DB 모델링·질의 최적화 역량을 보여준다.
- 복잡한 결제 도메인은 제외하고 정확성·성능·설계 근거에 집중한다.
- 최소 기능으로 빠르게 완성한다.

## 2. 사용자

| 사용자 | 목적 |
|---|---|
| 사용량 생산자 | 인스턴스 사용량 이벤트 발행 |
| `BILLING_ACCOUNT_VIEWER` | 소속 회사의 예상·확정 금액과 계산 근거 조회 |
| `BILLING_ACCOUNT_ADMIN` | Viewer 권한과 소속 회사 구성원의 과금 역할 관리 |

## 3. 범위

| 서비스 | 측정·과금 기준 |
|---|---|
| Compute | 온디맨드 VM 실행 초, 실행 1회당 최소 60초 |
| Storage | 연결된 블록 스토리지의 할당 용량과 시간 |
| Network | 외부 전송량 |

공통 조건은 `small`·`medium`·`large`, Linux, 단일 리전, KRW로 제한한다.

### 포함

- 표준 이벤트 수신·검증·저장과 시간 단위 집계
- 최근 집계 기준의 월 누적 예상 금액 계산
- 배치 재계산을 통한 스트리밍 결과 검증과 월간 금액 확정
- 예상·확정 금액 조회 API, 회사별 데이터 분리, 구성원 과금 역할 관리
- 기간·서비스·인스턴스 기준의 비용 탐색과 원본 사용량 상세 조회
- 사용량부터 확정 금액까지의 계산 근거 추적
- 내부 사용자 인증과 최소 웹 대시보드

### 제외

- 실제 결제, 세금, 환불, 미수금
- 할인·크레딧·Spot·예약 인스턴스·Savings Plan
- CPU·메모리·GPU 과금과 Windows 라이선스
- Object Storage, Managed Database, Load Balancer
- 실제 클라우드·외부 인증 제공자 연동, 상용 수준 UI
- 사용자 초대·계정 생명주기·복잡한 역할 체계
- 고객 API를 통한 월간 검증 실행·재실행
- 비용 예측·이상 탐지·태그·리전 분석·대량 내보내기

## 4. 기능 요구사항

| ID | 요구사항 |
|---|---|
| FR-01 | 인스턴스가 1분마다 발행하는 사용량 이벤트를 지속적으로 받는다. |
| FR-02 | 유효한 이벤트와 잘못된 이벤트를 구분한다. |
| FR-03 | 사용량을 지정된 시간 단위로 집계한다. |
| FR-04 | 월초부터 최근 집계 시점까지의 예상 금액과 기준 시각을 제공한다. |
| FR-05 | 사용자 조회를 중단하지 않고 월 사용량을 배치로 재계산해 스트리밍 결과를 검증하고 확정한다. |
| FR-06 | 두 역할은 소속 회사의 예상·확정 금액과 사용량·단가를 API로 조회한다. |
| FR-07 | `BILLING_ACCOUNT_ADMIN`은 소속 회사 구성원의 과금 역할을 조회·변경·제거한다. |
| FR-08 | 모든 사용자 API 요청에서 인증된 회사 소속과 역할을 확인한다. |
| FR-09 | 이벤트·집계·정산 결과의 전 과정에서 회사 식별자를 유지한다. |
| FR-10 | 등록된 사용자는 로그인·로그아웃하고 자신의 회사와 역할을 확인한다. |
| FR-11 | 웹 대시보드에서 예상·확정 금액과 계산 근거를 조회하고 Admin은 구성원 권한을 관리한다. |
| FR-12 | 역할은 회사 소속별로 부여하며 역할 변경과 접근 거부를 기록한다. |
| FR-13 | 최대 31일의 비용을 서비스·인스턴스로 필터링하고 일·서비스·인스턴스 단위로 그룹화해 추이, Top 10과 원본 사용량 상세를 조회한다. |

## 5. 적용 표준

| 대상 | 기준 |
|---|---|
| 이벤트 외형 | CloudEvents 1.0.2 JSON |
| 이벤트 내용 | 프로젝트 자체 `Instance Usage Event v1` |
| 시간 | UTC 기반 RFC 3339 |
| 정산 결과 | FOCUS 1.4 Cost and Usage 일부 |

FOCUS 적용 필드는 `ChargePeriodStart/End`, `BillingPeriodStart/End`, `ConsumedQuantity/Unit`, `PricingQuantity/Unit`, `BilledCost/Currency`, `ResourceId`, `ServiceName`이며 전체 준수를 주장하지 않는다.

## 6. 제약사항

- Java 21을 사용하고 나머지 기술은 아키텍처 설계에서 결정한다.
- 하나의 이벤트에 직전 1분의 실행 시간, 스토리지 용량, 외부 전송량을 담는다.
- 종료 시 1분 미만의 마지막 구간도 발행하고 금액은 초 단위로 계산한다.
- 가격 정책은 사용량과 단가의 곱으로 제한한다.
- 고객 RBAC는 `BILLING_ACCOUNT_VIEWER`, `BILLING_ACCOUNT_ADMIN` 두 역할로 제한한다.
- 회사와 역할은 클라이언트 입력이 아닌 인증된 소속 정보에서 결정한다.
- 인증은 등록된 내부 사용자만 다루며 회원가입·계정 복구·MFA는 제외한다.
- 월간 검증과 재처리는 고객 권한이 아닌 내부 작업으로 실행한다.
- 발생기에서 전송되지 않은 이벤트 탐지는 제외하고, 수신한 유효 이벤트의 내부 유실은 허용하지 않는다.
- 개발·테스트 환경은 프로젝트 내부에서 재현할 수 있어야 한다.
- 비용 탐색의 원본 사용량 상세는 읽기 전용 커서 페이지네이션으로 제공한다.

## 7. 미결 사항

- `Instance Usage Event v1` 필수 항목
- 월 마감 후 도착한 이벤트 처리 방식
- 정산 확정 시점과 재실행 기준

# Cloud Usage Billing 프로젝트 요구사항

## 1. 개요

클라우드 인스턴스가 발행하는 사용량 이벤트를 수집·집계하고, 이번 달의 현재까지 누적 예상 금액과 월간 확정 금액을 API로 제공하는 포트폴리오 프로젝트다.

## 2. 목표

- 이벤트 기반 데이터 파이프라인 설계 및 처리 역량을 보여준다.
- 대량 데이터 집계, 배치 처리, DB 모델링 및 질의 최적화 역량을 보여준다.
- 요구사항에서 설계 결정과 검증 결과까지 이어지는 과정을 설명할 수 있게 한다.
- 도메인 완성도보다 핵심 데이터 흐름의 정확성과 성능에 집중해 빠르게 완성한다.

## 3. 사용자

- **사용량 생산자**: 클라우드 인스턴스 또는 이를 모사한 프로그램
- **고객 사용자**: 자신의 월 누적 예상 금액과 월간 확정 금액을 조회하는 사용자
- **운영자**: 이벤트 처리 상태와 월간 정산 결과를 확인하는 사용자

## 4. 범위

### 포함

- 합의된 표준 형식의 사용량 이벤트 수신
- 이벤트 검증, 저장, 스트리밍 처리 및 시간 단위 집계
- 최근 집계 사용량을 이용한 이번 달 누적 예상 금액 계산
- 배치 재계산을 통한 스트리밍 집계 검증 및 월간 금액 확정
- 월 누적 예상 금액과 월간 확정 금액 조회 API
- 테넌트별 데이터 구분
- 사용량에서 정산 결과까지의 처리 내역 추적

### 제외

- 실제 카드 결제 및 결제대행사 연동
- 세금, 세금계산서, 환불 및 미수금 처리
- 약정 할인, 크레딧 등 복잡한 가격 정책
- 실제 클라우드 사업자와의 연동
- 완성도 높은 프론트엔드와 기업 수준의 인증·권한 관리

## 5. 기능 요구사항

- **FR-01** 시스템은 인스턴스가 1분마다 발행하는 표준 형식의 사용량 이벤트를 지속적으로 받을 수 있어야 한다.
- **FR-02** 시스템은 유효한 이벤트와 잘못된 이벤트를 구분할 수 있어야 한다.
- **FR-03** 시스템은 수신한 사용량을 지정된 시간 단위로 집계할 수 있어야 한다.
- **FR-04** 시스템은 이번 달 1일부터 최근 집계 완료 시점까지의 누적 예상 금액과 집계 기준 시각을 제공해야 한다.
- **FR-05** 시스템은 월별 사용량을 배치로 다시 계산하고 스트리밍 결과와 검증한 후 월간 금액을 확정해야 한다.
- **FR-06** 사용자는 API를 통해 월 누적 예상 금액과 월간 확정 금액을 조회할 수 있어야 한다.
- **FR-07** 운영자는 정산 결과가 어떤 사용량에서 계산되었는지 확인할 수 있어야 한다.

## 6. 적용 표준

- 사용량 이벤트는 CloudEvents 1.0.2 JSON 형식을 따른다.
- 이벤트의 과금 데이터는 프로젝트에서 정의하는 `Usage Event v1` 형식을 사용한다.
- 모든 시각은 UTC 기준 RFC 3339 형식으로 표현한다.
- 월간 정산 결과는 FOCUS 1.4의 Cost and Usage 용어와 필드 일부를 사용한다.
  - 사용 기간: `ChargePeriodStart`, `ChargePeriodEnd`
  - 정산 기간: `BillingPeriodStart`, `BillingPeriodEnd`
  - 사용량: `ConsumedQuantity`, `ConsumedUnit`
  - 가격: `PricingQuantity`, `PricingUnit`
  - 금액: `BilledCost`, `BillingCurrency`
  - 대상: `ResourceId`, `ServiceName`
- 복잡한 할인, 세금, 계약, 청구서가 범위에서 제외되므로 FOCUS 전체 준수를 주장하지 않는다.

## 7. 제약사항

- 포트폴리오를 빠르게 완성할 수 있도록 최소 기능만 구현한다.
- 데이터 파이프라인, 배치 처리, DB 활용과 성능 검증을 우선한다.
- 구현 언어는 Java 21을 사용한다.
- 인스턴스는 직전 1분의 사용량을 이벤트로 발행하고, 종료 시 남은 구간을 마지막 이벤트로 발행한다.
- 이벤트 발행 주기와 별개로 사용량과 금액은 초 단위까지 계산한다.
- 가격 정책은 사용량과 단가를 곱하는 수준으로 제한한다.
- 운영 환경과 데이터는 프로젝트 내부에서 재현 가능해야 한다.
- 나머지 기술 제품은 아키텍처 설계 단계 전까지 확정하지 않는다.

## 8. 미결 사항

- `Usage Event v1`의 필수 항목
- 중복·누락·순서 변경 이벤트의 처리 기준
- 월 정산 완료 후 도착한 이벤트의 반영 방식
- 정산 결과를 확정하는 시점과 재실행 기준

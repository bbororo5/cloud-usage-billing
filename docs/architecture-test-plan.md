# Architecture Test Plan

아키텍처 드라이버를 구현 전 테스트 계획과 연결하고, 구현 후 자동으로 검증한다.

## 테스트

| 대상 | 검증 | 통과 기준 | 실행 시점 |
|---|---|---|---|
| DR-01 | 중복·지연·순서 변경 처리와 배치 비교 | 중복 0건, 금액 차이 0원 | 매 커밋 |
| DR-02 | 초당 330건 지속 입력과 1,000건 최대 입력 | 유실 0건, 99%가 10초 이내 반영 | 주요 변경 후 |
| DR-03 | 1억 건에서 사용자 500명 동시 조회 | p95 1초, 데이터 지연 5분 이하 | 성능 검증 시 |
| DR-04 | 스트리밍·배치 강제 중단 후 재실행 | 중복 0건, 정상 실행과 차이 0원 | 매 커밋·주요 변경 후 |
| DR-05 | 다른 회사의 원본·집계·정산·캐시·구성원 접근과 범위 없는 조회 | 노출 0건 | 매 커밋 |
| DR-06 | 역할별 API 호출과 Admin 권한 제거 후 재호출 | 무권한 처리 0건, 이력 누락 0건 | 매 커밋 |
| 구조 | 모듈 책임과 의존 관계 검사 | 금지된 의존 0건 | 매 커밋 |

## 운영

| 구분 | 범위 |
|---|---|
| 빠른 테스트 | 작은 데이터로 정확성·재처리·회사 분리·역할 권한을 매 커밋 검증 |
| 통합 테스트 | 실제 데이터 흐름의 실패·복구를 주요 변경 후 검증 |
| 성능 테스트 | 처리량·동시 조회·대용량 성능을 별도로 실행하고 기록 |

## 준비 순서

1. 이벤트 형식 확정 후 테스트 이벤트와 발생기를 만든다.
2. 모듈 책임 확정 후 구조 테스트를 만든다.
3. API 계약과 권한표 확정 후 권한·부하 테스트를 만든다.
4. 스트리밍·배치 구현 전에 중복·실패·재실행 테스트를 만든다.

모든 ADR에는 관련 테스트와 통과 기준을 함께 기록한다.

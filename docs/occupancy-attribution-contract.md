# 점유 이력과 사용량 귀속의 연결 계약

## 상태와 목적

2026-09-24 기획 위임에 따라 결정. 구현·장애 검증 전이다.

**사용 구간까지 점유 이력이 빠짐없이 반영됐음을 확인한 뒤 회사에 공개한다.** 사용량과 점유 사실의 토픽 간 도착 순서에 의존하지 않는다. [ADR-009](adr/0009-occupancy-event-recovery-and-cache-consistency.md)의 공개 보류 결정을 구체화한다.

## 책임과 입력

| 책임 | 보장 |
|---|---|
| 외부 점유 사실 발행자 | VM별 시작·종료 사실과 ‘이 시각까지 이력 전달 완료’ 확인을 발행한다. VM 제어는 계속 외부 책임이다. |
| 점유 이력 모듈 | 사실을 PostgreSQL 원장·캐시에 반영하고, 조회 가능한 이력과 확인 범위를 같은 버전으로 제공한다. |
| 사용량 귀속 모듈 | 사용 구간 전체가 확인 범위 안에 있고 점유 회사가 유일할 때만 공개한다. |

‘확인 완료 시각’은 **추가하는 외부 입력 계약**이지 Kafka ACK·CloudEvents가 제공하는 보장이 아니다. 회사 정보 없는 기존 사용량 스키마와 Kafka→ClickHouse 수집 경로는 바꾸지 않는다.

## 확인 범위

- VM별 최초 기준 시각과 그때의 점유 상태를 등록한다. 기준 시각 이전은 확인된 이력으로 취급하지 않는다.
- 외부 발행자는 기준 시각부터 `T` 미만에 발생한 모든 점유 변경을 먼저 발행한 후 `T`까지의 완료 확인을 보낸다. 단순 현재 시각이나 일정 지연으로 완료를 추정하지 않는다.
- 사실과 완료 확인은 같은 점유 토픽·VM key를 사용한다. VM별 논리적 단일 발행자가 재시작에도 유지되는 연속 번호를 부여한다. 재전송은 같은 번호·내용을 유지하며, 번호 누락·내용 충돌은 진행을 막는다.
- 완료된 60초 사용 구간마다 그 종료 시각까지 확인을 제공한다. 사용량보다 확인이 먼저 도착할 필요는 없다. 외부가 변경 완료를 판단할 수 없다면 확인을 늦춘다.
- 내부 확인 범위는 해당 번호까지의 사실이 원장·캐시에 반영되고 처리 결과가 내구 기록된 뒤에만 전진한다. 캐시의 과거 이력과 더 새로운 확인 범위를 섞지 않는다.

이는 과거 사실을 빠뜨리지 않았다는 외부의 신뢰 계약이다. 포트폴리오에서는 확정된 점유 시나리오를 재생하는 발행기로 검증하며, 실제 데이터센터 연동을 구현했다고 주장하지 않는다.

## 귀속과 공개

사용 구간 `[a, b)`는 **기준 시각 ≤ a, b ≤ 내부 확인 완료 시각**, 유일한 점유 이력, 현재 유효한 이력 버전을 모두 만족해야 한다.

| 상태 | 처리 |
|---|---|
| 확인 미도착·번호 누락·부분 반영 | 원본을 보존하고 재처리 가능한 대기 상태로 둔다. 추측 귀속·공개·관련 정산 확정은 금지한다. |
| 확인 완료, 점유 이력 하나가 전체 구간 포함 | 해당 과거 회사에 귀속한다. 현재 점유자로 대체하지 않는다. |
| 확인 완료, 점유 없음·겹침·구간 불일치 | 귀속 오류로 보존·알림·격리한다. 해결 전 공개·관련 정산 확정을 막는다. |
| 같은 이벤트 재처리 | `source + id`의 귀속 결과를 중복 공개하지 않는다. |

완료 확인 이후의 정상 점유 변경은 확인된 과거 구간을 바꾸지 않는다. 늦은 사용량은 해당 과거 구간으로 처리한다. 대기 적체는 관측·알림 대상으로 두되 임의 TTL 폐기나 시간 경과에 따른 공개는 하지 않는다. 안전한 다른 구간은 계속 조회할 수 있다.

## 정정과 실패 경계

- 확인된 과거를 바꾸는 일반 사실은 계약 위반이다. 보존·알림하고 영향 구간의 추가 공개를 차단한다. 조용히 기존 이력을 덮어쓰지 않는다.
- 정정은 별도 절차다. 영향 구간의 조회·진행 중 공개를 차단한 뒤 이력 개정을 반영하고, 기존 귀속을 철회·재계산·검증한 후 다시 공개한다. 이미 전달된 응답을 회수할 수 있다고 가정하지 않는다.
- 공개 직전 버전 조회만으로 경합이 해결되지는 않는다. 차단과 진행 중 공개의 선후관계를 강제하는 저장·조회 구조는 LLD에서 증명해야 한다. 그전에는 이 계약을 구현 완료로 보지 않는다.

## 다음 설계

외부 사실·완료 확인의 정확한 스키마, 발행 번호 보존, 워커 내부 처리 구조, 원장·캐시의 동일 버전 읽기, 공개·정정의 원자적 경계와 재시작 복구를 정한다. 실행 위치는 ADR-011의 워커로 정했으며 캐시 제품은 미정이다. 기존 지연 목표는 유지하며 확인 전달 비용을 포함해 측정한다.

# API Contract v1

## 1. 목적

대시보드가 예상 비용·확정 정산·원본 사용량을 조회하고, Admin이 소속 회사의 과금 역할을 관리하는 계약을 정의한다.

상세 요청·응답은 [OpenAPI](../contracts/openapi.yaml)를 기준으로 한다. 그 안의 deprecated 수집 API는 이전 구현의 계약이며 신규 목표에서 제외한다.

## 2. API

| 영역 | Method | Endpoint | 기능 |
|---|---|---|---|
| 인증 | `POST` | `/api/v1/session` | 로그인 |
| 인증 | `DELETE` | `/api/v1/session` | 로그아웃 |
| 인증 | `GET` | `/api/v1/me` | 현재 사용자·회사·역할 조회 |
| 비용 | `GET` | `/api/v1/costs` | 최대 31일의 예상 비용 필터·그룹화·정렬 |
| 정산 | `GET` | `/api/v1/settlements/{billingMonth}` | 월간 확정 금액 조회 |
| 사용량 | `GET` | `/api/v1/usage-records` | 원본 사용량 상세 조회 |
| 권한 | `GET` | `/api/v1/billing-members` | 과금 구성원과 역할 조회 |
| 권한 | `PUT` | `/api/v1/billing-members/{userId}/role` | 역할 부여·변경 |
| 권한 | `DELETE` | `/api/v1/billing-members/{userId}/role` | 과금 역할 제거 |

## 3. 비용 조회

`GET /api/v1/costs` 하나가 화면 기획에 따라 총액·추이·구성·Top N을 만든다.

- `from`, `to`: 시작 포함·종료 제외, 최대 31일
- `from`, `to`는 UTC 분 경계이며 그 안에 완전히 포함된 사용 구간을 조회한다.
- 점유 시작 기준의 60초 구간이 조회·월 경계를 걸치는 처리 정책은 미결이며 [로드맵](implementation-roadmap.md)에서 추적한다.
- `serviceCategory`, `resourceId`: 선택 필터
- `groupBy`: `day`, `service`, `resource` 중 최대 2개
- `sort`, `direction`, `limit`: 정렬과 결과 제한
- 사용량 정렬은 단위가 하나로 제한되는 조회에서만 허용한다.
- 응답은 요청 기간과 실제 포함된 사용량의 가장 늦은 `ChargePeriodEnd`인 `dataAsOf`를 구분한다. 사용량이 없으면 `null`이며 발생기가 보내지 않은 이벤트의 완전성은 보장하지 않는다.
- 요청한 회사·범위에 공개 보류가 있으면 해당 요청 전체를 `503 / SERVICE_UNAVAILABLE`로 응답한다. 보류분을 제외한 부분 총계는 반환하지 않으며 다른 안전한 VM·구간의 독립 조회는 허용한다.

집계 결과는 제한된 크기로 반환한다. 원본 사용량만 `(ChargePeriodEnd, source, id, SkuMeter)` 기준의 불투명한 커서로 페이지네이션한다. 첫 페이지의 적재 기준 시각을 커서에 포함해 후속 페이지의 결과 집합을 고정한다.

## 5. 보안과 오류

- 세션은 비활동 30분 만료이며 별도 절대 만료는 없다. 서버 시각이 `마지막 접근 + 30분` 이상이면 `401`. 유효 세션으로 인증된 요청 시작 시 접근을 갱신하되 만료·폐기된 세션을 복원하지 않는다.
- 유효한 인증 세션의 재로그인은 `409 / SESSION_ALREADY_AUTHENTICATED`이며 기존 신원·세션 ID를 유지한다. 계정 변경은 로그아웃 후 로그인한다.
- 로그아웃 폐기 완료 뒤 세션을 검사하는 요청은 `401`. 이미 세션 검증을 마친 요청은 인가·공개 검사를 계속하며, 늦은 세션 저장으로 폐기를 되돌리면 안 된다.
- 인증 저장소 조회·저장·폐기 실패는 `503 / SERVICE_UNAVAILABLE`. 로그인·로그아웃 성공을 거짓 보고하지 않는다.
- 서비스 진입의 인가를 통과한 업무는 권한 변경·계정 차단으로 취소하지 않는다. 변경 완료 후 인가에는 현재 소속·역할을 적용하고 관련 세션은 폐기한다. 공개 가능성은 별도로 검사한다.
- 소속·권한 저장소 장애도 `503 / SERVICE_UNAVAILABLE`이며 과거 역할이나 기본 회사로 대체하지 않는다. 이 오류는 본인 정보와 모든 보호된 사용자 API에 적용한다.
- 사용자 API는 `tenantId`를 받지 않고 현재 세션의 회사 범위를 강제한다.
- 다른 회사의 자원과 사용자는 존재하지 않는 자원처럼 `404`로 처리한다.
- 역할 부족은 `403`, 미인증은 `401`로 처리한다.
- 역할 충돌과 마지막 Admin 제거는 `409`로 처리한다.
- 상태 변경 요청은 CSRF 토큰을 요구한다.
- 커서는 내용을 노출하지 않고 변조를 검증한다.
- 응답에는 내부 URL·SQL·테이블·Kafka topic/partition/offset·스택 트레이스를 포함하지 않는다.
- 오류 응답은 고정 코드와 `traceId`만 제공한다.
- 공개 판단은 서버에서 응답 내용을 확정하는 시점까지 보호한다. 관련 차단이 먼저 커밋되면 보류하고, 공개 판단이 먼저 확정되면 그 응답은 전송할 수 있다. 확정 전 부분 응답은 전송하지 않는다.
- 공개 보류·가격 누락·가격 사본 버전 불일치·의존 저장소 장애는 동일한 `503 / SERVICE_UNAVAILABLE` 형식으로 응답한다. 보류 원인·타사 또는 회사 미확정 입력의 존재·개수는 노출하지 않는다. 정상 빈 조회와 구분하며 0원으로 대신 응답하지 않는다.
- 위 공개 기준은 비용·사용량과 월간 확정 조회에 적용한다. 월간 확정 결과가 없는 경우의 `404`와 조회 자체의 보류·장애 `503`은 구분한다. 배치 실패만으로 모든 사용량 조회를 차단하지 않는다.

발생기는 사용자 API를 호출하지 않는다. Kafka 발행과 발생기 인증·검증은 [이벤트 계약](event-contract.md)을 따른다.

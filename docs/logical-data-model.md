# Logical Data Model

## 1. 목적과 사고 순서

조회 기능에서 필요한 결과를 정하고, 이를 재현할 사실과 소유자를 찾는다. 이후 관계·상태·불변식을 정의하고 실패 시에도 유지되는지 검증한다. 테이블·인덱스는 물리 모델에서 다룬다.

기능 → 보존할 사실 → 데이터 소유자 → 식별자·관계 → 상태·규칙 → 조회·실패 검증

논리 규칙과 구현 완료는 구분한다. 현재 구현 범위는 [로드맵](implementation-roadmap.md)을 따른다.

## 2. 데이터 소유권

원본은 생성·변경 권한을 가진 책임이 하나다. 전달 로그·사본·계산 결과를 같은 원본으로 취급하지 않는다.

| 데이터 | 소유 책임·저장소 | 다른 책임의 사용 |
|---|---|---|
| 사용자·회사·소속·세션·권한 감사 | 접근 통제 / PostgreSQL | BFF가 현재 소속·역할 확인 |
| 점유 이력·버전·제어 처리 결과 | 점유 관리 / PostgreSQL | 귀속 처리가 원장과 캐시로 확인 |
| 미검증 사용량·점유 제어 메시지 | 수신 로그 / Kafka | 보관 기간 안 재소비·복구 |
| 검증된 원시 사용량 | 원시 원장 / ClickHouse | 귀속·재계산의 근거, BFF 접근 금지 |
| 회사 귀속 조회 모델·귀속 오류 | 귀속 처리 / 조회 모델은 ClickHouse | BFF는 귀속 완료분만 조회 |
| SKU·가격 버전 | 가격 관리 / PostgreSQL | ClickHouse 가격 사본으로 계산 |
| 월 작업·실행·검증·확정 결과 | 정산 / PostgreSQL | BFF가 확정 결과 조회 |

Kafka는 유한 보관의 전달 로그이고 ClickHouse는 사용량의 장기 원장이다. 점유 캐시·가격 사본은 재생성 가능하며 원본을 수정하지 않는다. 오류 격리 저장 구조와 점유·귀속 처리의 실행 배치는 미정이다.

## 3. 사용자와 회사

사용자 신원과 회사에서의 권한은 수명이 다르므로 분리한다.

| 엔티티 | 식별자 | 책임 |
|---|---|---|
| User | UserId | 사용자 신원·활성 상태 |
| BillingAccount | BillingAccountId | 비용·정산의 회사 범위 |
| Membership | BillingAccountId + UserId | 소속의 활성 상태·역할 |
| AuthenticationSession | SessionId | 로그인 상태·만료·폐기 |
| AuditEvent | AuditEventId | 역할 변경·접근 거부의 행위자·시각·사유 |

- 한 사용자의 활성 소속은 최대 한 회사다. 역할은 User가 아니라 Membership에 둔다.
- Viewer는 조회, Admin은 자기 회사 구성원의 역할 관리까지 허용한다. 마지막 Admin은 제거할 수 없다.
- 역할 제거는 소속 권한을 끝내며 사용자와 과거 기록을 삭제하지 않는다.
- 세션은 사용자 식별자만 신뢰 근거로 삼는다. 회사·역할은 매 요청 현재 소속에서 확인한다.
- 역할 변경·관련 세션 폐기·감사 기록은 한 트랜잭션으로 처리한다. 감사에는 대상·변경 전후 역할을 남기되 비밀정보는 남기지 않는다.
- 인증은 ADR-005의 서버 세션이다. JWT 제안은 승인된 대체 결정이 아니다.

## 4. 사용량과 회사 귀속

VM 출처는 유지되지만 점유 회사는 바뀐다. 따라서 이벤트에 회사를 넣지 않고 **사용 시간과 점유 이력**으로 귀속한다.

| 엔티티 | 논리 식별자 | 책임 |
|---|---|---|
| UsageProducer | source | VM 출처 식별, 회사와 독립 |
| UsageEvent | source + id | 재전달돼도 같은 측정 사건 |
| RawUsageRecord | source + id + meter | 이벤트의 서비스별 측정값 |
| Allocation | 점유 이력 식별자 | source·회사·점유 시작/종료·버전 |
| AttributedUsageRecord | 회사 + source + id + meter | 회사가 확인된 조회용 사용량 |
| EventRejection | 거부 기록 식별자 | 계약·출처 검증 실패 위치와 사유 |
| AttributionError | 귀속 오류 식별자 | 원본·사용 구간·원인·해결 이력 |

### 입력과 중복

- CloudEvents 외형과 프로젝트 측정 계약을 구분한다. 입력에는 회사·가격·SKU가 없다.
- 이벤트 하나는 동일 자원·리전·60초 구간의 Compute·Storage·Network 3개 레코드다. 수량은 음수가 아닌 정수다.
- 점유 시작 기준 완성된 60초만 발행하고 종료 시 잔여 구간은 버린다. 유휴 중 정상 이벤트는 발행하지 않는다.
- Compute는 실행 여부가 아닌 독점 확보 초, Storage는 할당 GiB×초, Network는 전송 바이트다.
- Kafka ACK는 미검증 기록의 보존이다. 출처·계약 검증 후 유효 원장에 반영한다. key와 payload의 source는 신원 증명이 아니다.
- 물리 전달은 중복될 수 있지만 같은 논리 키는 비용에 한 번만 반영한다. 같은 키에 다른 payload가 있으면 오류이며 임의 사본을 선택하지 않는다.

필드와 검증 세부사항은 [이벤트 계약](event-contract.md)에 둔다.

### 점유 이력과 귀속

- 점유 구간은 시작 포함·종료 제외이며 한 VM의 점유가 겹치면 안 된다. 예약 독점 확보도 점유이며 실제 해제 시 끝난다.
- 사용 구간 전체를 포함하는 점유가 정확히 하나여야 한다. 다른 점유와 부분 중첩해도 오류다.
- 지연 사용량은 현재 회사가 아닌 사용 당시 회사에 귀속한다. 새 점유자가 이전 점유자의 사용량을 볼 수 없다.
- 이력 없음·중복 점유는 원본 보존 → 오류 격리 → 담당자 알림 → 수정 후 재처리한다. 해결 전 공개·관련 월 확정을 차단한다.
- 귀속 모델의 키에 회사가 있더라도 같은 원시 레코드를 두 회사에 공개할 수 없다. 이력 정정 후 재귀속 절차는 구현 전 설계한다.

### 변경과 캐시

원장은 PostgreSQL이며 캐시는 반복 읽기를 줄이는 사본이다. 캐시 누락만으로 미귀속을 판정하지 않고 원장을 조회한다.

- 점유 제어 메시지를 Kafka에 내구 기록하고 원장·캐시·처리 결과에 멱등 반영한 뒤 offset을 진행한다.
- VM별 버전으로 오래된 갱신을 거부한다. 이는 지연 사용량 폐기가 아니다.
- 변경 반영이 불완전하면 신규 재할당과 영향 구간 공개를 보류한다. 이미 시작한 귀속도 공개 시 안전성을 확인한다.
- 시작 요청은 접수 후 최대 60초 안 활성화하거나 만료한다. 재시도로 기한을 늘리지 않는다. 준비 상태는 과금하지 않는다.
- 실제 종료 사실은 만료시키지 않으며 캐시 실패로 과금 시간을 늘리지 않는다. 이전 점유의 지연 종료가 새 점유를 끝내면 안 된다.

상태 전이·완료 응답 유실·복구 조건은 [저장소 접근 계약](storage-access-contract.md#점유-요청-기한과-완료-조건)에 둔다.

## 5. 가격과 월간 정산

예상 금액은 원본이 아니라 계산 결과다. 확정 결과는 재현 가능한 실행 근거와 함께 별도로 보존한다.

| 엔티티 | 식별자 | 책임 |
|---|---|---|
| PricingSku / PriceRate | SkuId / PriceRateId | meter·unit에 맞는 가격과 유효 기간·버전 |
| CalculatedCharge | 귀속 사용량 + 적용 가격 | 재계산 가능한 비용, 예상 금액 별도 영속화 없음 |
| SettlementJob | 회사 + UTC 월 | 월 작업의 상태·동시 실행 제어 |
| SettlementAttempt | RunId | 한 번의 실행·실패·재시도 근거 |
| SettlementValidation | RunId | 데이터 이상·가격 버전·금액 차이 검증 |
| MonthlySettlement | 회사 + UTC 월 | 검증된 최종 금액, 확정 후 불변 |

- 가격은 KRW의 음수가 아닌 단가이며 새 가격 버전을 추가해 이력을 보존한다. 예상·정산은 같은 규칙을 사용한다.
- 가격 누락·중복·사본 버전 불일치는 오류다. 0원이나 오래된 가격으로 숨기지 않는다.
- 사용 구간을 완전히 포함하는 가격 하나를 선택하는 것이 현재 계약이다. 가격 경계를 걸치는 구간은 미결이며 임의로 분할하지 않는다.
- 회사·월별 실행은 하나만 허용한다. 실패 후에는 새 RunId로 재시도하며 이전 시도는 보존한다.
- 미해결 귀속 오류·데이터 이상 0건, 비교 금액 차이 0원을 확인한 뒤 PostgreSQL 한 트랜잭션으로 확정한다.
- 실행 중 결과는 공개하지 않고 기존 확정 결과를 덮어쓰지 않는다. 실제 결제·환불은 범위 밖이다.

## 6. 조회와 검증

BFF는 현재 인증된 회사로 PostgreSQL RLS와 ClickHouse 테넌트별 신원·Row Policy를 적용한다. 원시 원장 접근은 금지하며 귀속 완료 조회 모델만 읽는다. 캐시와 비동기 처리에도 같은 회사 범위를 유지한다.

| 기능·실패 | 모델이 보장해야 할 것 |
|---|---|
| 기간 비용·서비스/자원별 분석 | 원시 중복을 한 번만 반영하고 동일 가격 규칙 적용 |
| 사용량 상세·커서 | 회사 범위와 첫 페이지의 적재 기준 시각 유지 |
| 다른 회사 조회·역할 제거 | 저장소에서도 차단하고 현재 권한 반영 |
| 점유 변경·지연 이벤트 | 사용 시점의 회사에만 귀속 |
| 스트리밍·배치 재실행 | 유실·중복 과금·부분 확정 없음 |

dataAsOf는 조회된 사용량의 최대 종료 시각(없으면 null)이지 그 시각까지의 완전성 보증이 아니다. 남은 판단은 [로드맵](implementation-roadmap.md)에 모은다. 물리 정의는 [PostgreSQL](postgresql-physical-data-model.md)·[ClickHouse](clickhouse-physical-data-model.md), 테스트는 [검증 계획](architecture-test-plan.md)을 따른다.
